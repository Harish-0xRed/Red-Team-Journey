## 4. Check whether n8n was running

The user explained that n8n had been installed months earlier out of curiosity, explored for one or two days, and was no longer needed.

### Check running processes

```powershell
Get-CimInstance Win32_Process |
Where-Object {$_.Name -match "n8n|node"} |
Select-Object Name, ProcessId, ExecutablePath, CommandLine
```

A `node.exe` process was found at:

`C:\Program Files\Adobe\Adobe Creative Cloud Experience\libs\node.exe`

This was Adobe's Node.js executable, not evidence that n8n itself was running.

### Initial npm check

```powershell
npm list -g n8n
```

PowerShell blocked `npm.ps1` because script execution was disabled by the current execution policy. This was a PowerShell script-launch restriction; it did not prove npm or n8n was missing.

### Use the Windows command wrapper

```powershell
npm.cmd list -g n8n
```

Output:

```text
C:\Users\hr950\AppData\Roaming\npm
`-- n8n@1.102.3
```

This confirmed that n8n `1.102.3` was installed globally for the current Windows user.

### Check listening TCP ports

```powershell
Get-NetTCPConnection -State Listen |
Select-Object LocalAddress, LocalPort, OwningProcess
```

Observed listening ports:
- `49664`
- `445`
- `49673`
- `49666`
- `15292`
- `9013`

Port `5678`, n8n's usual default port, was not present. This means no listener on port 5678 was observed at that time; it does not rule out a different configured port.

## 5. Uninstall unused n8n and verify

Reason: n8n was no longer needed, and installed version `1.102.3` was within the affected range for CVE-2025-65964.

Uninstall command:

```powershell
npm.cmd uninstall -g n8n
```

Output:

```text
removed 1951 packages in 38s
```

Verification command:

```powershell
npm.cmd list -g n8n
```

Output:

```text
C:\Users\hr950\AppData\Roaming\npm
`-- (empty)
```

**Conclusion:** The global n8n package was successfully uninstalled from the current user's npm global package directory. This did not uninstall Node.js itself or Adobe's separate Node.js executable.

### Introduction to SIEM scenario

Simulated alert:
`Potential CryptoMiner Activity Observed`

Rule conditions:
- Event ID: `4688`
- Log source: `WindowsEventLogs`
- Process name contains `miner` or `crypt`

Matching process in the supplied event table:

`C:\Users\Chris\temp\cudominer.exe`

Associated host: `HR_02`
Associated user: `Chris`

The lab's expected response was to classify the simulated activity as a true positive and isolate the host.

**SOC lesson:** A process name matching a rule is not, by itself, proof of malicious activity in a real environment. Collect supporting evidence such as file path, command line, parent process, hash, signature, network activity, and user context before making a real-world classification.
