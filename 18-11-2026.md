### 1. The 4-Step Log Triage Framework (Sysmon Event ID 1)

* **Structured Forensic Triage (`Parent -> Child -> Arguments -> Pivots`):**
  * **Step 1 (Parent Context):** Evaluated `WmiPrvSE.exe` spawning `powershell.exe` as an indicator of programmatic or remote WMI execution (Lateral Movement / Remote Execution) rather than interactive user activity (`explorer.exe`).
  * **Step 2 (Child Binary Validation):** Verified the full `Image` path to rule out binary masquerading while flagging anomalous interactive shells spawned by system service providers.
  * **Step 3 (Command-Line Flag Dissection):** Broke down the attacker stealth and evasion switch set:
    * `-NoP` (`-NoProfile`): Skips loading user profile scripts to avoid administrative hooks or custom logging.
    * `-NonI` (`-NonInteractive`): Runs without an interactive prompt so background execution does not hang.
    * `-W Hidden` (`-WindowStyle Hidden`): Conceals the PowerShell console window from the user's desktop.
    * `-Exec Bypass` (`-ExecutionPolicy Bypass`): Overrides Windows script execution restrictions.
    * `-Enc` (`-EncodedCommand`): Passes a Base64-encoded UTF-16LE payload to bypass string-matching signatures and handle special characters cleanly.
  * **Step 4 (Blast Radius Pivoting):** Learned to copy the `ProcessGuid` of the suspicious `powershell.exe` event and query subsequent `Sysmon Event ID 1` logs where `ParentProcessGuid` matches that value to uncover every post-exploitation child command (`whoami.exe`, `schtasks.exe`, etc.), avoiding OS PID recycling collisions.
* **Base64 Payload Signature (`JAB` Prefix):** Recognized that in UTF-16LE Base64, the `JAB` prefix corresponds to a PowerShell `$` variable declaration (e.g., `JABjAGwAaQBlAG4AdAA9` $\rightarrow$ `$client=`), instantly signaling a potential TCP reverse shell payload.

### 2. PowerShell Fundamentals & Security Internals (MITRE ATT&CK T1059.001)

* **Under-the-Hood Architecture:** Understood that `powershell.exe` is merely the console host, whereas the true engine is the .NET assembly `System.Management.Automation.dll` running atop the .NET Common Language Runtime (CLR).
* **Unmanaged PowerShell & Fileless Execution:** Learned how attackers can load `System.Management.Automation.dll` directly into custom C# programs to run PowerShell without spawning `powershell.exe`, and use the .NET CLR to invoke Win32 APIs directly in RAM without writing binaries to disk.
* **PowerShell vs. Command Prompt (`cmd.exe`):** Differentiated `cmd.exe` (unstructured plain-text pipeline, limited CLI access, minimal internal logging) from PowerShell (structured .NET object pipeline, full WMI/COM/.NET/Registry access, rich security telemetry).
* **Cmdlets & Attacker Aliases:** Studied the `Verb-Noun` cmdlet architecture and mapped high-risk aliases commonly abused in compact attack one-liners:
  * `iex` $\rightarrow$ `Invoke-Expression` (executes raw strings as code in memory).
  * `iwr` / `wget` / `curl` $\rightarrow$ `Invoke-WebRequest` (downloads web payloads).
  * `irm` $\rightarrow$ `Invoke-RestMethod` (fetches remote script text).
* **Execution Policies vs. Security Boundaries:** Confirmed that `ExecutionPolicy` (`Restricted`, `RemoteSigned`, etc.) is a user safety guardrail rather than a security boundary, easily bypassed without admin rights via `-ep bypass`, `-enc`, or piping input into `iex`.
* **Legitimate vs. Suspicious PowerShell Detection Matrix:**
  * Mapped key indicators in `Sysmon Event ID 1`: stealth flags (`-w hidden`, `-nop`), in-memory download cradles (`Net.WebClient`, `DownloadString`), code execution (`IEX`), raw socket creation (`System.Net.Sockets.TcpClient`), and PowerShell Version 2 downgrade attacks (`-v 2`).
* **Deep Defenses against Obfuscation:**
  * **PowerShell Script Block Logging (`Event ID 4104`):** Captures the full, de-obfuscated plain-text code block in memory right before execution, exposing `-enc` Base64 payloads.
  * **AMSI (Antimalware Scan Interface):** Routes decoded in-memory script buffers through `amsi.dll` to the EDR/Antivirus engine before execution.

## 💡 Lessons Learned

* An interviewer handing over a raw log snippet is testing structured analytical reasoning—evaluating parent lineage, command-line stealth flags, and `ProcessGuid` pivoting provides a complete incident narrative even before decoding an obfuscated payload.
* Relying on PowerShell Execution Policy for endpoint protection is ineffective; true defense requires combining `Sysmon Event ID 1` (process lineage and flags) with `PowerShell Event ID 4104` (de-obfuscated script block logging) and AMSI.
