## Lessons Learned

* Wireshark is not only about knowing filters; understanding the underlying networking concepts is essential for correctly interpreting packets.
* TCP connection establishment follows the basic pattern:
  `SYN → SYN-ACK → ACK`
* TCP Sequence Number tells where transmitted data starts.
* TCP Acknowledgment Number tells the sender the next byte the receiver expects.
* TCP Window Size is related to flow control, not packet size.
* MTU = maximum IP packet size allowed on a link.
* MSS = maximum TCP payload carried in a segment.
* MAC addresses belong to the Ethernet/Data Link layer.
* IP addresses belong to the Network layer.
* Port numbers help identify the application/service using TCP or UDP.
* DNS queries ask for information, while DNS responses provide the requested information.
* HTTP GET/POST packets can reveal application-layer requests when the traffic is not encrypted.
* TLS Client Hello and Server Hello are important indicators of the beginning of a TLS connection.
* ICMP Echo Request and Echo Reply represent the normal packet exchange used by ping.
* TTL can provide useful clues about packet routing and sometimes the originating operating-system family, but it should not be treated as definitive OS identification.
* DSCP is related to traffic classification/QoS, while ECN is related to congestion notification.
* The most important Wireshark skill is being able to move from:
  `Packet List → Packet Details → Packet Bytes → Network Meaning`
