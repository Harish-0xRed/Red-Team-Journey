## 🔐 Understanding the TLS Handshake

### Why TLS Exists

- Reviewed why plain TCP communication is insecure.
- Understood that anyone positioned between a client and server can read unencrypted data.
- Learned that TLS protects data before it travels across the network.

---

### TLS Handshake Workflow

Studied the complete communication flow before any encrypted data is exchanged.

```text
Client
   │
   │ ClientHello
   ▼
Server

Client
   ▲
   │ ServerHello
Server

Client
   ▲
   │ Certificate
Server

Client
   ▲
   │ Key Agreement
Server

───────────────

Shared Secret Created

───────────────

Encrypted Communication Begins
```

---

### ClientHello

Learned that the client begins the connection by sending:

- Supported TLS version
- Supported cipher suites
- Client random value
- Supported key exchange methods
- Additional TLS extensions

This message does **not** contain any passwords or sensitive information.

---

### ServerHello

Learned that the server replies with:

- Selected TLS version
- Selected cipher suite
- Server random value
- Key exchange information

Both the client and server now possess unique random values used later during key generation.

---

### Digital Certificate

Learned that the server presents its digital certificate to prove its identity.

Observed certificate details such as:

- Subject
- Issuer
- Public Key
- Validity Period

Connected this concept with the OpenSSL output seen during Bandit Level 15.

---

### Shared Secret Concept

Began studying how two computers create the same shared secret without directly sending that secret across the network.

Understood that:

- The client never sends its private value.
- The server never sends its private value.
- Only public values are exchanged.
- Both sides independently calculate the same shared secret.

This concept introduced the foundation of the **Diffie–Hellman Key Exchange**.

---

### Diffie–Hellman Introduction

Started learning Diffie–Hellman using small numbers.

Concepts introduced:

- Public values
- Private values
- Public keys
- Shared secret
- Modular arithmetic (`mod`)

Although the complete mathematics is still being studied, the core idea behind secure key exchange is now much clearer.

---

## 💡 Key Lessons Learned

- TLS Handshake occurs **before** encrypted communication begins.
- ClientHello and ServerHello negotiate communication parameters.
- The server proves its identity using a digital certificate.
- Public information can safely travel across the network.
- Private values never leave their respective systems.
- Both computers independently calculate the same shared secret.
- Modern TLS security relies on mathematical properties rather than exchanging encryption keys directly.
