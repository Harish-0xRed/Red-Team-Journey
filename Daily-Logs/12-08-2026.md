### TCP/IP

- Continued the Web Fundamentals learning path with TCP/IP.
- Reviewed the relationship between IP and TCP.
- Understood that IP is responsible for addressing and routing packets toward the destination.
- Understood that IP itself does not provide packet ordering or error checking.
- Learned that TCP works together with IP to provide reliable and ordered communication.
- Understood that TCP maintains a connection between the sender and receiver.

### TCP 3-Way Handshake

- Reviewed how TCP establishes a connection before application data is transmitted.
- Learned the three steps of the TCP handshake:
  - SYN → Client requests a TCP connection.
  - SYN-ACK → Server responds to the connection request.
  - ACK → Client confirms the connection.
- Understood that after the three-way handshake, the TCP connection is established and application data can be transmitted.
- Connected the TCP handshake with the HTTP request process learned previously.

### TCP Sequence Numbers

- Learned that TCP sequence numbers represent the position of data in the TCP byte stream.
- Understood that a TCP sequence number is not simply a packet number.
- Practiced calculating the next sequence number using the segment length.
- Example: if a segment starts at sequence 1000 and contains 500 bytes, the next expected sequence number is 1500.
- Understood that sequence numbers allow TCP to identify missing portions of the data stream.

### TCP Acknowledgment Numbers

- Learned that the TCP acknowledgment number represents the next sequence number the receiver expects.
- Practiced understanding ACK numbers when TCP segments are received successfully.
- Example: if the receiver has received bytes 1000–1499, it can send ACK 1500.
- Understood that ACK 1500 means the receiver has received everything before sequence 1500 and expects sequence 1500 next.
- Learned that the receiver does not need to know the total size of the application data to send an ACK.
- Understood that ACK numbers are about the next expected sequence number, not about confirming individual packet numbers.

### TCP Missing Segment Concept

- Practiced a TCP example where one segment was lost.
- Example:
  - Segment A → Seq 1000, Length 500
  - Segment B → Seq 1500, Length 500
  - Segment C → Seq 2000, Length 500
- If Segment B is missing, the missing sequence range is 1500–1999.
- The receiver can continue sending ACK 1500 because sequence 1500 is still the next expected data.
- Understood how sequence numbers and ACK numbers allow TCP to identify a gap in the data stream.
- Connected this concept to TCP retransmission, which will be studied next.

### Wireshark — Section 7.5 TCP Analysis

- Started learning Wireshark's TCP Analysis section.
- Learned that Wireshark's TCP dissector tracks the state of TCP sessions and adds analysis information when potential TCP problems are detected.
- Learned the concept of the Next Expected Sequence Number.
- Understood that Wireshark calculates the next expected sequence using the previous sequence number and segment length.
- Example:
  - Sequence = 1000
  - Segment Length = 500
  - Next Expected Sequence = 1500

### TCP Previous Segment Not Captured

- Learned the basic meaning of the Wireshark `TCP Previous Segment not captured` analysis flag.
- Understood that Wireshark can identify a sequence gap when the current sequence number is greater than the next expected sequence number.
- Example:
  - Expected Sequence = 1500
  - Current Sequence = 2000
  - 2000 is greater than 1500, indicating a gap before the current segment.
- Learned that `TCP Previous Segment not captured` does not automatically prove that a packet was lost on the network.
- It means that Wireshark did not see the expected previous segment in the capture.

## 💡 Lessons Learned

- IP and TCP have different responsibilities:
  - IP → Addressing and Routing
  - TCP → Reliable and Ordered Communication
- TCP sequence numbers track the position of data in the TCP byte stream.
- TCP acknowledgment numbers indicate the next sequence number expected by the receiver.
- TCP does not normally acknowledge individual packet numbers; ACK numbers represent the next expected sequence.
- Sequence numbers and ACK numbers work together to identify missing data.
- Wireshark can track TCP session state and identify possible TCP problems.
- Real packet captures helped connect the TCP theory learned from documentation with actual network traffic.
- Reconnected previous Cisco networking knowledge with the current Web Fundamentals learning path.
