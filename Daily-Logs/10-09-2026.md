  - **Routing** → connects/delivers traffic between networks.

### Wireshark Tools and Capture Utilities

- Clarified the difference between Wireshark and other packet-capture utilities.
- Learned that **Wireshark** is a GUI packet capture and packet-analysis application.
- Learned that **TShark** provides command-line packet analysis from the Wireshark ecosystem.
- Learned that **tcpdump** is a separate command-line packet capture/analyzer tool and does not require Wireshark to perform a capture.
- Understood that a capture created with `tcpdump` can later be opened and analyzed in Wireshark.
- Clarified that `sshdump` is a Wireshark extcap mechanism for obtaining packet captures remotely through SSH.
- Understood that the word **dump** generally relates to capturing/outputting data and does not represent a new network protocol.

### Wireshark — Capture Options

- Reached **Section 4.5 — The "Capture Options" Dialog Box** in the Wireshark User's Guide.
- Reviewed the meaning of the **Buffer** option:
  - A buffer is temporary memory used to hold captured packet data while the capture system processes it.
  - If packets arrive faster than they can be processed and available buffering is exhausted, packet drops can occur.
- Reviewed **Monitor Mode**:
  - Used for wireless 802.11 capture.
  - Allows capturing raw 802.11 headers when supported by the hardware, driver, interface, and operating system.
  - Enabling it may disconnect the wireless interface from its current network.
- Reviewed **Optimize**:
  - Controls optimization applied when compiling capture filters into BPF bytecode.
  - Normally should remain enabled.
- Reviewed **Capture Filter**:
  - Determines which packets are captured in the first place.
  - Distinguished capture filtering from later display filtering.

### Linux / BPF

- Learned that Wireshark capture filters are implemented using **BPF (Berkeley Packet Filter)** mechanisms.
- Understood the basic flow:
  - Capture filter → BPF instructions → kernel evaluates packets → matching packets are captured.
- Learned that **BPF JIT (Just-In-Time compilation)** can improve BPF filter execution performance on Linux.
- Understood that the BPF JIT setting shown in the Wireshark guide is a Linux power-user optimization and is not required for the current learning setup.

## 💡 Lessons Learned

- Packet capture is not simply about starting Wireshark; the capture location, network topology, interface, privileges, and capture configuration all affect what can be observed.
- **Promiscuous mode and routing are completely different concepts.**
- IP/MAC addresses can help identify or filter traffic from a particular machine, but they do not automatically make that machine's traffic visible to Wireshark.
- Wireshark is not the only packet-capture tool; tools such as `tcpdump` and TShark serve different purposes.
- Wireshark can be used as the main visual analysis tool while command-line tools can be useful for lightweight or remote environments.
- A **capture filter** decides what traffic is captured, while later filtering can be used to inspect relevant packets.
- Buffers temporarily hold captured packets so the system can process them.
- BPF is involved in efficient packet filtering, and BPF JIT can optimize its execution on Linux.
