## Today's Learning

### Attack & Detect Lab — PowerShell Foundations

Studied the Microsoft Learn material about Windows PowerShell and its role in system administration and automation.

Topics covered:

- PowerShell as an automation solution made up of:
  - A command-line shell
  - A scripting language
  - A configuration-management framework
- PowerShell compared with the traditional Windows command-line interface (`cmd.exe`).
- PowerShell command-line features:
  - Command history
  - Tab completion and prediction
  - Command and parameter aliases
  - Pipeline support
  - In-console help
- PowerShell works with .NET objects, not only plain text.
- The pipeline (`|`) passes output from one command to another.
- Cmdlets commonly use the `Verb-Noun` naming convention.
  - Example: `Get-Process`
  - `Get` identifies the action.
  - `Process` identifies the resource.
- `Get-Command` can be used to discover commands registered in the PowerShell session.
- PowerShell scripting can combine commands to automate administrative tasks.
- PowerShell Desired State Configuration (DSC):
  - Declarative configurations
  - Repeatable deployments
  - Enforcing configuration settings
  - Detecting configuration drift
  - Push and pull deployment models
- Difference between the two main PowerShell platforms:
  - Windows PowerShell: Windows-only, based on .NET Framework, with version 5.1 integrated into Windows 10 and Windows 11.
  - Modern PowerShell: cross-platform, based on modern .NET, and available on Windows, macOS, and Linux.
