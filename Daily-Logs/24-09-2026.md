## 💡 Lessons Learned & Incident Analysis

### 🔍 The Mistake Analysis
1. **The MAC Address Mix-up:** Pulled the wrong physical hardware signature by tracking the *source* MAC address of an inbound packet from the Server rather than checking the *destination* MAC or tracking an outbound frame directly initiated *by* the victim IP address.
2. **The Full Name Oversight:** Overlooked the plain-text payload layers within the SAMR protocol response stream where the account login string and the legal name were grouped closely together.

### 🛡️ The Advanced Remediation & Takeaways
- **Directional Flow Verification:** In an MNC interview or active incident, always verify packet direction (`Src` vs `Dst`) to avoid misidentifying a core server or default gateway as the physical victim device.
- **Fail-safe Search Mapping:** If a direct name string search (`cname`) or identity protocol (`ldap`) fails because it didn't trigger during the capture window, shift strategically to backing protocols like **NTLMSSP**, **SMB2 Session Setups**, or **SAMR structures**. 
- **The Engineer Mindset:** Technical mistakes in the packet trenches are not failures—they are structural learning adjustments. Adapting, pivoting, and understanding *how* a data structure behaves is infinitely more valuable than trying to guess the right answer on the first attempt.
