### 3. Windows Process Internals & Lifecycle
* **Program vs. Process vs. Thread:** A program is a static PE binary on disk; a process is an active resource container in virtual memory; a thread is the fundamental unit of CPU execution sharing the process's memory space.
* **Kernel vs. User Structures:**
  * **`EPROCESS` (Ring 0 / Kernel Mode):** Holds core accounting data, security tokens, and retains the `ExitStatus` until all open handles to a terminated process are closed.
  * **`PEB` (Process Environment Block — Ring 3 / User Mode):** Holds user-accessible process metadata (`CommandLine`, `BeingDebugged` flag, and loaded module lists). Studied how attackers manipulate the PEB for command-line spoofing and dynamic API resolution (PEB walking).
* **The Role of `ntdll.dll`:** Learned how user-mode applications transition from Ring 3 to Ring 0 via `ntdll.dll` (`NtCreateUserProcess`), loading the System Service Number (SSN) into the `EAX` register and executing the `syscall` instruction into `ntoskrnl.exe` (SSDT).
* **EDR Hooking vs. Direct Syscalls:** Understood how user-mode EDRs hook `ntdll.dll` functions and why kernel-level drivers like `SysmonDrv.sys` still catch direct syscall evasion inside Ring 0.

### 4. Process Trees & Ancestry in SOC Investigations
* **Windows Boot Lineage:** Traced standard parent-child relationships (`System` $\rightarrow$ `smss.exe` $\rightarrow$ `wininit.exe` $\rightarrow$ `services.exe` $\rightarrow$ `svchost.exe`, and `winlogon.exe` $\rightarrow$ `userinit.exe` $\rightarrow$ `explorer.exe`).
* **Spotting Anomalous Lineage:** Learned how to catch Living off the Land Binaries (LOLBins) by analyzing suspicious parents (e.g., `WINWORD.EXE` or `w3wp.exe` spawning `powershell.exe` or `cmd.exe`, or `svchost.exe` spawned by anything other than `services.exe`).
* **Sysmon Ancestry Fields:** Differentiated between `Image` vs. `ParentImage` (full disk paths to prevent binary masquerading) and `ProcessGuid` vs. `ProcessId` (preventing PID recycling collisions during backward and forward kill-chain tracing).

## 💡 Lessons Learned

* Default Windows Event Logs are blind to credential dumping (`lsass.exe` memory reads) and out-of-the-box command-line arguments unless supplemented by kernel telemetry like Sysmon (`Event ID 1` & `Event ID 10`).
* Because the PEB lives in User Mode (Ring 3), malware can tamper with its own command-line display after launch; capturing arguments at kernel creation time via Sysmon prevents this evasion.
* A SOC analyst doesn't stop at a single alert; tracing `ParentProcessGuid` backward reveals the Initial Access vector, while tracing `ProcessGuid` forward exposes the full post-exploitation blast radius.
