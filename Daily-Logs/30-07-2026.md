- Learned that SSH refuses to use private keys with insecure permissions.
- Fixed the warning:

  `UNPROTECTED PRIVATE KEY FILE`

- Practiced securing a private key using:

```bash
chmod 600 sshkey.private
```

## 💡 Lessons Learned

- SSH supports both password-based and key-based authentication.
- The `-i` option specifies the private key file used by SSH.
- A private key is used directly by SSH and should not be decoded.
- `scp` uses `-P` for the port, while `ssh` uses `-p`.
- Absolute file paths must be written correctly.
- SSH enforces strict permissions on private keys to protect authentication credentials.
- Reading Linux error messages carefully often leads directly to the solution.
