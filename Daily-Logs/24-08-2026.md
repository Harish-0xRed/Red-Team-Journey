## 📚 Today's Learning

### HTTP & Web Fundamentals (Section 5 to Section 9)

#### HTTP Status Codes (Section 5)
- Understood status code ranges: `1xx` (Informational), `2xx` (Success), `3xx` (Redirection), `4xx` (Client Error), and `5xx` (Server Error)[cite: 2].
- Analyzed critical response codes: `200 OK`, `201 Created`, `301/302 Redirects`, `400 Bad Request`, `401 Unauthorized`, `403 Forbidden`, `404 Not Found`, `405 Method Not Allowed`, and `500 Internal Server Error`[cite: 2].
- Learned the key triage difference: `403 Forbidden` means the resource exists but access is blocked (target for bypasses); `404 Not Found` means non-existent; `500 Server Error` indicates backend application crashes/injection points[cite: 2].

#### HTTP Headers (Section 6)
- Examined Request Headers: `Host` (Host Header injection), `User-Agent` (WAF bypass), `Cookie` (Session hijacking), `Authorization` (JWT attacks), and `X-Forwarded-For` (IP spoofing)[cite: 2].
- Analyzed Response Headers: `Set-Cookie`, `Location`, `Server`, `X-Powered-By` (Fingerprinting), `Content-Security-Policy` (XSS mitigation), and `Strict-Transport-Security` (HSTS)[cite: 2].
- Practiced reading and dissecting live response headers using `curl -I`[cite: 2].

#### Cookies and Sessions (Section 7)
- Deep-dived into state management: Cookies live on the client browser; Sessions reside on the backend server[cite: 2].
- Studied essential cookie security flags:
  - `HttpOnly`: Blocks JavaScript access via `document.cookie` (mitigates XSS cookie theft)[cite: 2].
  - `Secure`: Ensures cookies are only transmitted over encrypted HTTPS connections[cite: 2].
  - `SameSite=Strict/Lax`: Defends against Cross-Site Request Forgery (CSRF)[cite: 2].
- Analyzed JSON Web Tokens (JWT) structure: `header.payload.signature` and decoded claims using `base64 -d`[cite: 2].

#### HTTPS and TLS (Section 8)
- Explored why plain HTTP is vulnerable to cleartext sniffing over port 80[cite: 1, 2].
- Walked through the step-by-step TLS Handshake: Client/Server Hello, Certificate Validation, Key Agreement, and Secure Tunnel Establishment[cite: 2].
- Reinforced the distinction: HTTPS secures the network connection in transit, but does not fix application-layer vulnerabilities (SQLi, IDOR, XSS)[cite: 2].
- Connected practical tools: `nc` for raw plaintext (Bandit 14) vs. `openssl s_client` for TLS-wrapped endpoints (Bandit 15)[cite: 2].

#### How Websites Work & Attack Surface (Section 9)
- Mapped out the full stack architecture: Browser ➔ Web Server (Nginx/Apache) ➔ Application Backend (Python/PHP/Node) ➔ Database (MySQL/PostgreSQL)[cite: 2].
- Compared traditional multi-page document architectures with modern JSON-driven REST APIs[cite: 2].
- Evaluated the layered attack surface across Frontend, HTTP Headers, Web Server, Backend Logic, Database, and Authentication systems[cite: 2].

## 💡 Lessons Learned
- A `500 Internal Server Error` is often a direct indicator that an untrusted input broke backend code or database queries[cite: 2].
- Cookies serve as the access key to a server-side session; acquiring a valid session cookie bypasses primary login controls[cite: 2].
- Client-side validations (HTML/JS) can always be bypassed by crafting direct requests via `curl` or Burp Suite[cite: 2].
- The presence of HTTPS indicates encryption on the wire, not that the destination website or its backend code is secure[cite: 2].
