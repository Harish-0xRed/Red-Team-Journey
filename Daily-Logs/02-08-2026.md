## 📚 Today's Learning

### TLS - Module 4 (Certificates & Trust)

Today was dedicated to understanding **how browsers verify the identity of websites before establishing a secure HTTPS connection**.

---

## 🔐 Public Key vs Private Key

### Public Key

- Learned that the **Public Key** is intentionally shared with everyone.
- Understood that browsers use the server's public key to encrypt data before sending it.
- Anyone can obtain the public key without compromising security.

### Private Key

- Learned that the **Private Key never leaves the server**.
- Only the server possesses the matching private key.
- Only the matching private key can decrypt data encrypted using its corresponding public key.

---

## 📄 Digital Certificates

Learned that a digital certificate is more than just a public key.

A certificate contains:

- Website identity (Domain Name)
- Public Key
- Issuer (Certificate Authority)
- Validity Period
- Digital Signature

The certificate acts as the website's digital identity card.

---

## 🏛 Certificate Authorities (CA)

Studied the role of Certificate Authorities.

Learned that:

- Browsers trust certificates signed by trusted CAs.
- CAs verify the ownership of a domain before issuing a certificate.
- Browsers maintain a built-in list of trusted Certificate Authorities.

Examples discussed:

- Let's Encrypt
- DigiCert
- Sectigo
- GlobalSign

---

## ⚠ Self-Signed Certificates

Connected today's learning with Bandit Level 15.

Observed the OpenSSL output:

```text
subject=CN=SnakeOil
issuer=CN=SnakeOil
```

Learned that:

- The same entity created and signed the certificate.
- Browsers cannot independently verify its identity.
- Encryption still works, but trust cannot be established automatically.

---

## 🧠 Mentor Discussion

Explored an attack scenario:

> "What happens if an attacker copies Google's certificate and places it on a malicious website?"

Key conclusions:

- The browser compares the requested domain with the certificate's domain.
- A certificate issued for `google.com` cannot be used for `evil.com`.
- Any modification to the certificate invalidates its digital signature.
- Simply copying a certificate cannot impersonate another website.

---

## 🔑 Public Key Cryptography Discussion

Started exploring why public and private keys work together.

Current understanding:

- Public Key encrypts data.
- Private Key decrypts data.
- The certificate contains only the public key.
- The private key is never included inside the certificate.
- Public and private keys are mathematically related but serve different purposes.

This topic will be studied in greater depth later while learning RSA and public-key cryptography.

---

## 💡 Key Lessons Learned

- Encryption and trust are two different concepts.
- A certificate proves the identity of a website.
- Browsers verify certificates before trusting a connection.
- Copying another website's certificate does not allow impersonation.
- The private key remains secret on the server and is never shared.
- HTTPS security depends on both cryptography and certificate validation.
