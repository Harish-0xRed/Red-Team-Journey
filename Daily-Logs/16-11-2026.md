## 2. Topics Learned

### A. Windows Process

A process is an instance of a program that is currently running on a Windows computer.

Example:
- `notepad.exe` stored on disk is a program.
- When Notepad starts running, Windows creates a process.
- Windows assigns a Process ID (PID) to identify it.

### B. Parent and Child Processes

A parent process is the process that starts another process.

A child process is the newly created process.

Example:

```text
cmd.exe
   |
   └── powershell.exe
```

- `cmd.exe` is the parent.
- `powershell.exe` is the child.

**SOC relevance:** The parent process helps an analyst understand how a suspicious process was started. An unusual parent process may require investigation.

### C. PowerShell — Dual-Use Tool

PowerShell is a command-line shell and scripting language used to manage and automate Windows systems.

Administrators use it for:
- Managing processes and services.
- Managing users and permissions.
- Reading system information.
- Automating administrative tasks.

Attackers may misuse PowerShell for:
- Executing unwanted commands.
- Downloading or running malicious code.
- Collecting system information.
- Performing unauthorized activities.

**Important concept:** PowerShell is a dual-use tool. Its presence alone does not mean malicious activity.

### D. Sysmon Event ID 1

Sysmon Event ID 1 records process creation.

Useful event information can include:
- Process image and path.
- Process ID.
- Command line.
- Parent process.
- User account.
- Executable hashes, depending on configuration.

**Remember:**
- Event ID 1 = Process Creation.
- Event ID 5 = Process Termination.

A Sysmon event is telemetry, not automatic proof of an attack.

### E. Encoded PowerShell Commands

An encoded command is not automatically malicious.

Legitimate scripts and applications can also use encoded commands.

When investigating suspicious encoded PowerShell activity, examine:
- Command-line arguments.
- Parent process.
- User account.
- Process path.
- Timestamp.
- Related events and network activity.

The command should be decoded safely for inspection, never executed just to understand its contents.

### F. Detection vs. Investigation

**Detection:** A security system identifies activity matching a suspicious pattern.

**Investigation:** An analyst examines evidence to determine what actually happened.

An alert is a starting point for investigation, not a final conclusion.

## 3. Windows Process Lifecycle

Learned the conceptual stages of a process lifecycle:

1. **Creation:** Windows receives a request to start a program and creates a process.
2. **Initialization:** Windows prepares memory and other required resources.
3. **Execution:** The process runs its instructions.
4. **Waiting or Running:** The process may run on the CPU or wait for input and other resources.
5. **Termination:** The process finishes or is stopped, and Windows releases its resources.

### Important Terms

| Term | Meaning |
|---|---|
| PID | Process ID |
| Memory space | Virtual memory assigned to a process |
| Handle | Reference used to access a system resource |
| Thread | Unit of execution inside a process |

**Process vs. Thread:**
A process provides the environment and resources for a running program. A thread executes instructions inside that process. A process can contain multiple threads.

## 5. SOC Analyst Thinking

Today's important lesson:

**Never classify activity as malicious based on one indicator alone.**

Investigation chain:

1. Identify the alert.
2. Examine the process and command line.
3. Check the parent process and user.
4. Correlate related events.
5. Verify the evidence.
6. Reach a conclusion based on the available evidence.
